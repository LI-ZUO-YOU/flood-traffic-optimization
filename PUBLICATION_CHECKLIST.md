# Publication checklist

Before responding to the editor:

1. Confirm that all authors approve public release of the data and code.
2. Add the authors' chosen license if reuse should be permitted.
3. Create a public GitHub repository and upload the complete contents of this directory.
4. Upload with Git or GitHub Desktop, not the browser: the package contains one 53.7 MB file, while browser uploads are limited to 25 MiB per file. No individual file exceeds GitHub's 100 MB command-line limit; Git LFS is not required.
5. Add final creator metadata through `CITATION.cff` or `.zenodo.json` before the first release. If both are present, Zenodo uses `.zenodo.json` for the archived record.
6. Link the GitHub account in Zenodo, sync the repository list, and enable this repository for automatic archiving.
7. Only after Zenodo shows the repository as enabled, create and publish GitHub release `v1.0` from the exact uploaded files.
8. Wait for Zenodo to ingest the release, then record the GitHub URL, Zenodo record URL, and DOI.
9. Insert those values into the manuscript Data Availability Statement and the response to the Editor.
10. Open both public links in a private browser window before resubmission.
11. Keep the archived release unchanged; publish a new version if corrections are required.
